AI agent with deterministic guardrails

A model that plans on-chain actions, never trusted to sign them.

  LLM ─ proposes
    │
    ▼  quote · simulate
  [ policy check ]
    │
    ▼  deterministic code
       disposes
Stack
TypeScript · NestJS · LLM tool calling · EVM
Surface
Natural-language intent → executed trade
Hard part
Usefulness and trustworthiness come from opposite properties

01 — The problem

A language model planning on-chain actions is useful precisely because it is not deterministic — it can handle an instruction nobody wrote a branch for. That is the same property that makes it unsafe to hand a signing key.

The naive integration gives the model tools and lets it call them. That works in a demo and fails the first time a malformed plan, a hallucinated address or a prompt-injected instruction reaches something irreversible.

02 — Approach

The model proposes, deterministic code disposes. The agent produces a structured plan, never a transaction. Everything after that is ordinary software: quotes fetched across venues, the plan simulated against current state, then the same policy layer that guards human-initiated actions evaluates it.

A model-initiated action gets no special path and no elevated authority. If it exceeds a limit or targets an address outside the allowlist, it is refused exactly as a human request would be.

Every step the model touches is recorded and replayable — the prompt, the plan, the quotes, the simulation result, the policy verdict — so a bad outcome can be reconstructed rather than guessed at.

03 — Trade-offs

The agent is slower and narrower than letting it call tools freely, and a meaningful share of what it proposes is rejected before execution. That is the design working, not failing — but it does mean the demo is less impressive than the unconstrained version.

It also moves the hard problem rather than removing it: the policy layer now has to be right, and expressing intent as a structured plan is real engineering work that grows with each new action type.
