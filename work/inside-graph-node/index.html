Operating it, not just deploying to it
Question
Read side or money path?

01 — The contract you sign

Three files define everything: a manifest saying what to watch and from which block, a schema defining entities as tables, and mappings compiled to WASM that turn events into entities. graph-node is the runtime — it ingests blocks, runs handlers, stores entities and serves GraphQL — and it guarantees that the same manifest produces the same data everywhere. That guarantee is why mappings must be deterministic: no clock, no randomness, no HTTP.

02 — How reorgs are free

Every save() writes a version row carrying the block range it is valid for. Time-travel queries fall out of that design, and so does reorg handling: reverting means dropping versions whose range opens after the fork point. The ingestor keeps recent ancestors and detects forks by parent hash, with a configurable maximum depth it will tolerate.

You write no reorg code — but your dashboards still see numbers move backwards for a few seconds, so the application layer cannot pretend it did not happen.

03 — Operating it

The indexing-status endpoint is the real monitoring surface: synced, health, fatal error, and the gap between chain head and latest indexed block. Alert on that gap. A handler that throws stops the subgraph at that block until a fix is deployed, and a schema change means re-indexing from scratch — which is why grafting exists, letting a new version continue from an existing one, and why pruning exists to stop version history from filling the database.

graph-node also needs a good RPC underneath it, which is where this connects back to the gateway work.

04 — The decision it forces

A subgraph gives you reorg handling and time travel for free, in exchange for fixed GraphQL, no aggregation, no joins against off-chain data and no non-deterministic logic. That makes it excellent for a read side and wrong for a ledger.

The rule I settled on: subgraph for the read side, custom indexer for the money path — both reading the same chain, neither acting as the other's source of truth.
