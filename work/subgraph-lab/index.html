01 — What it is

The complete indexing stack on one machine: graph-node, IPFS, PostgreSQL and an anvil dev chain, plus a small ERC-20-style contract, a subgraph project and four scripts that take it from nothing to a working GraphQL query.

Deploy the contract, generate events, build the mapping to WASM, deploy the subgraph, query it. Every step runs; nothing is described and skipped.

02 — Verified output

After seeding one mint and two transfers, the query returns totals of three transfers, 1350 volume and 1000 minted, with balances of 650 and 350 across two accounts — and the indexing status reports synced with the latest block matching the chain head.

Those numbers are from an actual run, not an expectation written in advance.

03 — Two things the docs do not warn you about

graph-cli 0.97 requires an explicit immutable argument on every @entity directive. Omit it and the build fails with a message that reads like a schema error rather than a version requirement.

graph-node spends about a minute on Postgres migrations on first start. Deploy during that window and you get a connection reset that looks like a configuration problem but is just a race. The deploy script waits for the status port before proceeding, which is the fix.

Both cost real time to diagnose, which is exactly why a lab that actually runs is worth more than a tutorial that describes the same steps.
