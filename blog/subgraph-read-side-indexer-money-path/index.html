Subgraph for the read side, custom indexer for the money path

A rule I arrived at after building both. The deciding factor is not query convenience — it is what happens to your balances during a reorg.

Every team indexing chain data eventually asks whether to write a subgraph or build their own indexer. The usual framing is convenience against control, and that framing produces the wrong answer about half the time.

What a subgraph gives you for free

Deploy a manifest, a schema and some mappings, and graph-node handles ingestion, storage and a GraphQL API. Two things it handles that people underestimate:

Reorgs. Entities are stored as versions keyed by block range, so reverting a fork is deleting versions rather than repairing rows. You write no reorg code.

Time travel. Querying state as of block N falls straight out of the same design.

Both are genuinely hard to build well, and getting them free is a real argument.

What it takes away

Mappings must be deterministic: no clock, no randomness, no HTTP calls. GraphQL is fixed — no arbitrary aggregation, no joins against your off-chain tables. A schema change means re-indexing from scratch.

Each of those is survivable for a dashboard. None of them is survivable for a ledger.

The deciding question

Not "which is easier" but what happens to this data during a reorg.

For a transaction history view: entities vanish and reappear over a few seconds, a chart twitches, nobody loses anything. Perfect fit.

For a balance that determines whether a withdrawal is allowed: the same revert silently changes the number your business logic just read. That is not a rendering artifact, it is a financial one — and it needs a confirmation policy tiered by value, an idempotent ledger and an audit trail, none of which a subgraph is built to express.

The rule

Subgraph for the read side, custom indexer for the money path. Both reading the same chain, neither acting as the other's source of truth.

In practice that also means the display balance and the spendable balance are allowed to disagree briefly — and the system has to be honest about which one it is showing.
