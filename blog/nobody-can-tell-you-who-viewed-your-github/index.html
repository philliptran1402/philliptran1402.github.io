Nobody can tell you who viewed your GitHub profile

There is no LinkedIn-style visitor list, the view counter badge cannot identify anyone, and the tracking-pixel trick does not work. Here is what is actually measurable.

I went looking for a way to see who had been visiting my GitHub profile. The short answer is that it does not exist, and the reason it does not exist is more interesting than the question.

Why the counter badge cannot know

Those Profile views: N badges are third-party image endpoints that increment on each request. They produce a count, never an identity — and the count is approximate.

The mechanism is the reason: GitHub proxies every image in rendered Markdown through its own camo service. The server behind the badge sees a request from GitHub's proxy, not from the person reading the page. No visitor IP, no user agent, nothing to identify.

That same proxy is why the classic tracking-pixel trick does not work here. It is not a gap waiting to be exploited; it is the point of the design.

What is actually measurable

Followers, stargazers, watchers, forkers. Real names, and a much stronger signal than a view — someone took an action.

Repository traffic insights. Under Insights → Traffic, for repositories you can push to: views, unique visitors, and referring sites, for the last fourteen days. Counts only, no identities.

The referrer column is the useful one. Knowing that traffic came from LinkedIn rather than from a search is more actionable than knowing one stranger's username.

LinkedIn is the only platform in this stack that genuinely answers "who looked at me", which is worth remembering when deciding where to spend effort.

The result that actually mattered

I pulled my own numbers expecting to tune something. Views across my repositories over fourteen days: zero. Followers: five, of which four were my own alternate accounts.

No amount of analytics fixes that, because there was nothing to analyse. The problem was not measurement, it was that the work worth looking at was sitting in a private repository.

Which is the actual lesson: instrumentation is useful once there is traffic. Before that, it is a way to feel productive while avoiding the harder task of publishing something.
