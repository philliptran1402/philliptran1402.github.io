The gateway, not the node, is what makes self-hosting trustworthy

Running your own node fixes cost, privacy and latency. It does not fix the failure that actually hurts, because your node can lag too.

The self-hosting conversation usually runs on cost. Compute units get expensive, eth_getLogs is priced like a luxury good, so you run your own node and the bill flattens out.

That reasoning is fine and it misses the failure that actually costs money.

Five ways a provider URL hurts you

A single RPC endpoint can: lie by serving a head from forty minutes ago, rate-limit you in the middle of a volatile market, reprice as you scale, observe every address you care about, and add latency by living on another continent.

Self-hosting fixes four of those. It does not fix the first one — because your own node lags too, crashes too, and needs patching on fork day like everything else.

A lying upstream returns 200

This is what makes staleness nastier than downtime. An endpoint that is down returns an error and your retry logic handles it. An endpoint that is behind returns a valid response with old data, and every consumer downstream acts on it confidently.

A node cannot detect its own lag either. eth_syncing returning false means the node believes it is caught up. A node isolated from its peers believes that too, at a head from an hour ago.

The only way to detect it is to compare against a second source. That is an architectural property, not a configuration flag — which is why no amount of node tuning gets you there.

What the gateway does

Every service talks to one internal URL. Behind it: probe each upstream's head on a short interval, mark anything too far behind the best as lagging and route around it, fail over on errors, cap eth_getLogs ranges before they reach a node, allowlist methods so admin_ and debug_ are unreachable, and rate-limit so one buggy loop cannot take the node down.

The design decision worth defending: when only lagging sources remain, refuse to answer. For anything that signs transactions, an error is recoverable and a stale answer is not.

The shape of the answer

Self-host for cost, privacy and latency. Put a gateway in front for correctness. Keep a provider as a fallback upstream rather than as the primary.

Hybrid is not a compromise here — it is the only arrangement where you can tell that one of your sources is wrong.
